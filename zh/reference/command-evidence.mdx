这些命令生成可审计证据。`verify` 执行验证命令，`review record` 记录评审结论，`evidence` 记录人工验证、制品审批或导入 CI 证据。

## `verify` {#verify}

执行功能声明的全部自动验证命令并记录结果。

```bash
npx @caesarlo/sdlc-harness verify <feature-id>
```

| 参数 | 类型 | 必填 | 默认值 | 说明 |
| --- | --- | --- | --- | --- |
| `<feature-id>` | string | 是 | — | 要验证的功能 ID。功能不能包含 `manual` 验证项。 |

Team 模式要求功能已有有效 claim。Solo 模式在必要时为 `defaultOwner` 建立 30 分钟临时 claim，并在命令结束时释放。任一验证命令失败时仍会记录证据，但命令返回非零。

## `evidence manual` {#manual}

为一个 `manual` 验证项记录人工证据。

```bash
npx @caesarlo/sdlc-harness evidence manual <feature-id> \
  --verification <index> --result <passed|failed> \
  --notes <text> [--actor <id>]
```

| 参数 | 类型 | 必填 | 默认值 | 说明 |
| --- | --- | --- | --- | --- |
| `<feature-id>` | string | 是 | — | 必须处于 `in_progress` 的功能 ID。 |
| `--verification` | integer | 是 | — | 从 `1` 开始的正整数序号，必须指向 `type: manual` 的验证项。 |
| `--result` | enum | 是 | — | 仅允许 `passed` 或 `failed`。 |
| `--notes` | string | 是 | — | 非空验证说明；含空格时使用引号。 |
| `--actor` | string | 否 | `defaultOwner` | 执行人工验证的主体标识。 |

## `review record` {#review-record}

为当前 commit 记录评审结论。

```bash
npx @caesarlo/sdlc-harness review record <feature-id> \
  --reviewer <id> --summary <text> [--result <passed|failed>]
```

| 参数 | 类型 | 必填 | 默认值 | 说明 |
| --- | --- | --- | --- | --- |
| `<feature-id>` | string | 是 | — | 必须处于 `in_progress` 的功能 ID。 |
| `--reviewer` | string | 是 | — | reviewer 标识；完成门禁要求它不同于 claim owner。 |
| `--summary` | string | 是 | — | 非空评审摘要。 |
| `--result` | enum | 否 | `passed` | 仅允许 `passed` 或 `failed`。 |

## `evidence approval` {#approval}

记录与当前文件内容哈希绑定的项目级审批。

```bash
npx @caesarlo/sdlc-harness evidence approval <artifact> \
  --actor <id> --summary <text>
```

| 参数 | 类型 | 必填 | 默认值 | 说明 |
| --- | --- | --- | --- | --- |
| `<artifact>` | path string | 是 | — | 仓库内现存文件。不能是 `feature_list.json`。 |
| `--actor` | string | 是 | — | 审批主体标识，不能为空。 |
| `--summary` | string | 是 | — | 非空审批依据或结论。 |

文件内容改变后，原审批的内容哈希不再匹配，状态会显示为失效。

## `evidence import` {#import}

验证并导入 GitHub Actions run 作为测试证据。

```bash
npx @caesarlo/sdlc-harness evidence import <feature-id> \
  --ci-run <run-id> [--owner <github-owner>] [--repo <github-repo>]
```

| 参数 | 类型 | 必填 | 默认值 | 说明 |
| --- | --- | --- | --- | --- |
| `<feature-id>` | string | 是 | — | 接收 CI 证据的功能 ID。 |
| `--ci-run` | string | 是 | — | GitHub Actions run ID。 |
| `--owner` | string | 条件必填 | 从 `origin` 推断 | GitHub 仓库 owner。无法从 `origin` 推断时必须提供。 |
| `--repo` | string | 条件必填 | 从 `origin` 推断 | GitHub 仓库名。无法从 `origin` 推断时必须提供。 |

本机必须安装并认证 `gh` CLI，且 token 能读取目标 run。只有 `status=completed` 且 `conclusion=success` 的真实 run 才能导入。
