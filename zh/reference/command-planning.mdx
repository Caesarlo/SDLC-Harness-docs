规划命令向 `feature_list.json` 增加里程碑或功能。命令使用比较并交换式写入并拒绝重复 ID。交互命令执行各自说明中的输入检查；完整的 schema 和 structural 写前预检仅适用于 `new-feature --input`。

## `new-feature` {#new-feature}

交互创建功能，或从仓库内 JSON 文件导入功能。

```bash
npx @caesarlo/sdlc-harness new-feature
npx @caesarlo/sdlc-harness new-feature --input planning/feature.json
```

| 参数 | 类型 | 必填 | 默认值 | 说明 |
| --- | --- | --- | --- | --- |
| `--input` | path string | 否 | — | 仓库内现存 JSON 文件的相对路径。指定后使用非交互模式。 |

输入对象可以直接是功能对象，也可以写成 `{ "feature": { ... } }`。`id`、`milestone`、`behavior` 和非空 `verification` 数组必填；`milestone` 必须已存在。新功能只能是 `not_started`，不能预置 `claim`、`workspace` 或 `evidence`。写入前，此模式会针对候选功能列表运行 `[schema]`、`[structural]`、`[dependency-cycles]`、`[milestone-order]` 和 `[stage-gate]` 检查。完整字段定义见 [`feature_list.json` 参考](/zh/reference/feature-list)。

未指定 `--input` 时，命令依次询问 ID、里程碑、标题、可观察行为、owner、验证命令、依赖、来源引用和 priority。priority 必须是整数，数值越小越先被 `claim --next` 选择。

## `new-milestone` {#new-milestone}

交互创建里程碑。

```bash
npx @caesarlo/sdlc-harness new-milestone
```

该命令没有 CLI 参数。它交互询问里程碑 ID、标题和目标。ID 必须唯一；成功后向 `feature_list.json` 追加里程碑。

## `milestone archive` {#milestone-archive}

把一个已完成的里程碑及其全部功能从 `feature_list.json` 移入 `.harness/archive/<milestone-id>.json`。

```bash
npx @caesarlo/sdlc-harness milestone archive M1 --actor alice
```

| 参数 | 类型 | 必填 | 默认值 | 说明 |
| --- | --- | --- | --- | --- |
| `--actor` | string | 否 | `harness.config.json.defaultOwner` | 记录到归档文件的 `archived_by` 字段和 `milestone.archived` 审计事件中的身份标识。 |

该里程碑下的每个功能都必须已经是 `passing`；否则命令会拒绝执行并列出阻塞的功能，不会做任何改动。归档文件会在里程碑从 `feature_list.json` 移除之前写入，因此中途中断最多留下重复的归档记录，绝不会丢失里程碑数据。

已归档的功能不会从项目历史中消失——它们仍然满足新功能的依赖检查（`claim`、`feature start`、`dependency-cycles`），`traceability` 也仍会把它们计入对应需求、用户故事和验收标准的覆盖。归档只是把已完成的工作挪个地方存放，让新里程碑从一份精简的 `feature_list.json` 开始，绝不会使已交付的成果失效。归档文件的结构见 [归档里程碑](/zh/reference/feature-list#archiving-milestones)。

## `milestone list-archived` {#milestone-list-archived}

列出已归档的里程碑。

```bash
npx @caesarlo/sdlc-harness milestone list-archived
```

该命令没有参数，也不会修改仓库。它输出一个 JSON 数组，包含每个已归档里程碑的 `id`、`title`、功能数量和 `archived_at`/`archived_by`。
