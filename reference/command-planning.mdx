Planning commands add milestones or features to `feature_list.json`. They use compare-and-swap writes and reject duplicate IDs. Interactive commands perform their documented input checks; the full schema and structural preflight applies specifically to `new-feature --input`.

## `new-feature` {#new-feature}

Create a feature interactively or import one from a JSON file in the repository.

```bash
npx @caesarlo/sdlc-harness new-feature
npx @caesarlo/sdlc-harness new-feature --input planning/feature.json
```

| Argument | Type | Required | Default | Description |
| --- | --- | --- | --- | --- |
| `--input` | path string | No | — | Relative path to an existing JSON file in the repository. When specified, the command runs non-interactively. |

The input can be a feature object directly or `{ "feature": { ... } }`. `id`, `milestone`, `behavior`, and a non-empty `verification` array are required. The `milestone` must already exist. A new feature can only have the `not_started` status and cannot include a preconfigured `claim`, `workspace`, or `evidence`. Before writing, this mode runs `[schema]`, `[structural]`, `[dependency-cycles]`, `[milestone-order]`, and `[stage-gate]` checks against the candidate feature list. See the [`feature_list.json` reference](/reference/feature-list) for the full field definitions.

Without `--input`, the command prompts for the ID, milestone, title, observable behavior, owner, verification commands, dependencies, source references, and priority. Priority must be an integer. Lower values are selected first by `claim --next`.

## `new-milestone` {#new-milestone}

Create a milestone interactively.

```bash
npx @caesarlo/sdlc-harness new-milestone
```

This command has no CLI arguments. It prompts for the milestone ID, title, and objective. The ID must be unique. On success, it appends the milestone to `feature_list.json`.
