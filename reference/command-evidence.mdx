These commands produce auditable evidence. `verify` executes verification commands, `review record` records a review conclusion, and `evidence` records manual verification, artifact approval, or imported CI evidence.

## `verify` {#verify}

Execute every automated verification command declared by a feature and record the results.

```bash
npx @caesarlo/sdlc-harness verify <feature-id>
```

| Argument | Type | Required | Default | Description |
| --- | --- | --- | --- | --- |
| `<feature-id>` | string | Yes | — | Feature ID to verify. The feature cannot contain `manual` verification items. |

Team mode requires the feature to have an active claim. In Solo mode, the command creates a temporary 30-minute claim for `defaultOwner` when necessary and releases it when the command ends. If any verification command fails, evidence is still recorded, but the command exits nonzero.

## `evidence manual` {#manual}

Record manual evidence for one `manual` verification item.

```bash
npx @caesarlo/sdlc-harness evidence manual <feature-id> \
  --verification <index> --result <passed|failed> \
  --notes <text> [--actor <id>]
```

| Argument | Type | Required | Default | Description |
| --- | --- | --- | --- | --- |
| `<feature-id>` | string | Yes | — | ID of a feature that must be `in_progress`. |
| `--verification` | integer | Yes | — | Positive, 1-based index that must point to a `type: manual` verification item. |
| `--result` | enum | Yes | — | Accepts only `passed` or `failed`. |
| `--notes` | string | Yes | — | Non-empty verification notes. Use quotes when they contain spaces. |
| `--actor` | string | No | `defaultOwner` | Identifier of the actor performing manual verification. |

## `review record` {#review-record}

Record a review conclusion for the current commit.

```bash
npx @caesarlo/sdlc-harness review record <feature-id> \
  --reviewer <id> --summary <text> [--result <passed|failed>]
```

| Argument | Type | Required | Default | Description |
| --- | --- | --- | --- | --- |
| `<feature-id>` | string | Yes | — | ID of a feature that must be `in_progress`. |
| `--reviewer` | string | Yes | — | Reviewer identifier. The completion gate requires it to differ from the claim owner. |
| `--summary` | string | Yes | — | Non-empty review summary. |
| `--result` | enum | No | `passed` | Accepts only `passed` or `failed`. |

## `evidence approval` {#approval}

Record project-level approval bound to the hash of the current file content.

```bash
npx @caesarlo/sdlc-harness evidence approval <artifact> \
  --actor <id> --summary <text>
```

| Argument | Type | Required | Default | Description |
| --- | --- | --- | --- | --- |
| `<artifact>` | path string | Yes | — | Existing file in the repository. It cannot be `feature_list.json`. |
| `--actor` | string | Yes | — | Non-empty identifier of the approving actor. |
| `--summary` | string | Yes | — | Non-empty approval basis or conclusion. |

After the file content changes, the original approval's content hash no longer matches and its status becomes invalid.

## `evidence import` {#import}

Validate and import a GitHub Actions run as test evidence.

```bash
npx @caesarlo/sdlc-harness evidence import <feature-id> \
  --ci-run <run-id> [--owner <github-owner>] [--repo <github-repo>]
```

| Argument | Type | Required | Default | Description |
| --- | --- | --- | --- | --- |
| `<feature-id>` | string | Yes | — | Feature ID that receives the CI evidence. |
| `--ci-run` | string | Yes | — | GitHub Actions run ID. |
| `--owner` | string | Conditionally | Inferred from `origin` | GitHub repository owner. Required when it cannot be inferred from `origin`. |
| `--repo` | string | Conditionally | Inferred from `origin` | GitHub repository name. Required when it cannot be inferred from `origin`. |

The `gh` CLI must be installed and authenticated locally, and its token must be able to read the target run. Only a real run with `status=completed` and `conclusion=success` can be imported.
