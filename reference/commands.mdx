所有命令都在目标仓库根目录运行。使用 `npx sdlc-harness`，或在全局安装后使用 `sdlc-harness`。

## 初始化与状态

| 命令 | 作用 |
| --- | --- |
| `sdlc-harness init [--force]` | 在空仓库或新仓库中生成完整 harness。`--force` 允许覆盖冲突文件，请谨慎使用。 |
| `sdlc-harness adopt` | 向已有仓库添加缺失文件，不覆盖已有文件。 |
| `sdlc-harness validate` | 运行全部结构与治理检查。失败时以非零状态退出。 |
| `sdlc-harness status` | 以 JSON 输出各状态功能数量、当前功能和里程碑数量。 |

## 规划

| 命令 | 作用 |
| --- | --- |
| `sdlc-harness new-milestone` | 通过交互问答创建里程碑。 |
| `sdlc-harness new-feature` | 通过交互问答创建功能及其行为、验证、依赖和来源引用。 |

## 验证与证据

### 运行功能验证

```bash
sdlc-harness verify <feature-id>
```

实际执行功能的所有 `verification` 命令，并写入测试证据。这是本地生成 `kind: "test"` 证据的受支持方式。

### 导入 GitHub Actions 证据

```bash
sdlc-harness evidence import <feature-id> --ci-run <run-id> [--owner <o>] [--repo <r>]
```

工具会通过 `gh api` 独立确认运行存在、已经完成且结论成功。仍在运行、失败或不存在的 run 不会被导入。

## claim 与租约

<Note>
  这一节只在 `harness.config.json` 的 `collaborationMode` 为 `"team"` 时需要手动操作。默认的
  `"solo"` 模式下，`sdlc-harness verify` 会在运行前自动为 `defaultOwner` 认领功能、结束后自动释放，
  你通常不需要直接调用 `claim`/`release`。两种模式的取舍见[配置参考](/reference/configuration#harness-config-json)。
</Note>

```bash
sdlc-harness claim <feature-id> [--owner <name>] [--actor <id>] [--ttl <minutes>]
sdlc-harness claim --next [--owner <name>] [--actor <id>] [--ttl <minutes>]
sdlc-harness claim renew <feature-id> [--owner <name>] [--ttl <minutes>]
sdlc-harness claim <feature-id> --takeover-expired [--owner <name>]
sdlc-harness release <feature-id> [--owner <name>]
```

`--next` 只选择 `not_started`、未被有效认领且所有依赖已 `passing` 的功能。

跨机器同步 claim：

```bash
sdlc-harness claim <feature-id> --push [--remote origin] [--branch main]
```

## workspace

| 命令 | 作用 |
| --- | --- |
| `workspace create <feature-id> [--base <branch>]` | 为已认领功能创建 worktree 和 `feature/<id>` 分支。 |
| `workspace status` | 以 JSON 列出 workspace、claim 和磁盘状态。 |
| `workspace remove <feature-id> [--force]` | 移除 workspace。未提交或未推送内容默认阻止删除。 |
| `workspace prune` | 清理 claim 已释放或过期的安全 workspace；不安全项会被跳过。 |

完整命令写法：

```bash
sdlc-harness workspace create <feature-id> --base main
sdlc-harness workspace status
sdlc-harness workspace remove <feature-id>
sdlc-harness workspace prune
```

## GitHub provider

```bash
sdlc-harness provider github check [--owner <o>] [--repo <r>] [--branch <b>]
```

未提供 owner/repo 时，工具会尝试从 `origin` URL 推断。该命令需要 GitHub CLI `gh`。

## 常用参数

| 参数 | 默认值 | 说明 |
| --- | --- | --- |
| `--owner <name>` | `harness.config.json` 的 `defaultOwner` | claim 负责人 |
| `--actor <id>` | owner | 区分同一 owner 下的 Agent 会话 |
| `--ttl <minutes>` | `120` | claim 租约时长 |
| `--remote <name>` | `origin` | `claim --push` 使用的远程 |
| `--branch <name>` | `main` | push 或 provider 检查的目标分支 |
| `--base <branch>` | `main` | 创建 workspace 的基线分支 |
| `--force` | 关闭 | 覆盖初始化冲突或强制移除 workspace，具体取决于命令 |

<Warning>
  `--force` 可能覆盖文件或移除含未保存工作的 workspace。先阅读命令报告的冲突或风险。
</Warning>
