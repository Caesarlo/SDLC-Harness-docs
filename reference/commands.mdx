## Repository and governance

| Command | Purpose | Argument reference |
| --- | --- | --- |
| `init [--force]` | Generate the complete protocol. By default, stop and list conflicts when files already exist. | [View `init` arguments →](/reference/command-repository#init) |
| `adopt` | Insert only missing files. Generate a sidecar when `AGENTS.md` already exists. | [View `adopt` details →](/reference/command-repository#adopt) |
| `validate` | Run every governance audit and exit nonzero on failure. | [View `validate` details →](/reference/command-repository#validate) |
| `status` | Output a JSON summary of features, approvals, traceability, and next steps. | [View `status` details →](/reference/command-repository#status) |
| `traceability` | Output the complete traceability matrix and exit nonzero when actual gaps exist. | [View `traceability` details →](/reference/command-repository#traceability) |

## Feature lifecycle

| Command | Status transition | Argument reference |
| --- | --- | --- |
| `feature start <feature-id>` | Check readiness, dependencies, and WIP, then claim the feature and move it to `in_progress`. | [View `start` arguments →](/reference/command-feature#start) |
| `feature complete <feature-id>` | Check evidence and independent review, then move the feature to `passing`. | [View `complete` arguments →](/reference/command-feature#complete) |
| `feature block <feature-id>` | Record a blocker, release the claim, and move the feature to `blocked`. | [View `block` arguments →](/reference/command-feature#block) |
| `feature reopen <feature-id>` | Clear the blocker and move the feature from `blocked` to `not_started`. | [View `reopen` arguments →](/reference/command-feature#reopen) |

## Claims and leases

| Command | Purpose | Argument reference |
| --- | --- | --- |
| `claim <feature-id>` | Claim a specific feature. | [View `claim` arguments →](/reference/command-claim#claim) |
| `claim --next` | Select a ready feature by dependency status, priority, and list order. | [View `--next` arguments →](/reference/command-claim#next) |
| `claim renew <feature-id>` | Renew an existing claim from the current time. | [View `renew` arguments →](/reference/command-claim#renew) |
| `claim <feature-id> --takeover-expired` | Take over an expired claim. | [View takeover arguments →](/reference/command-claim#takeover-expired) |
| `claim <feature-id> --push` | Claim, commit, and push. Try the next feature after a remote conflict. | [View `--push` arguments →](/reference/command-claim#push) |
| `release <feature-id>` | Release the claim and return `in_progress` to `not_started`. | [View `release` arguments →](/reference/command-claim#release) |

<Note>
  Solo mode usually does not require manual claims. `verify` temporarily claims the feature for `defaultOwner` when needed and releases it afterward. Team mode requires an active claim in advance.
</Note>

## Common defaults

| Argument | Default |
| --- | --- |
| Claim and lifecycle `--owner` | `harness.config.json.defaultOwner` |
| GitHub repository `--owner` for `provider github check` and `evidence import` | Inferred from `origin`; required when it cannot be inferred |
| `--ttl` | 120 minutes |
| `--remote` | `origin` |
| `--branch` | `main` |
| `--base` | `main` |

The default for `--actor` varies by command. See the corresponding argument page.

<Warning>
  `init --force` and `workspace ... --force` can overwrite files or discard uncommitted or unpushed work. Read the corresponding argument page and command output before using them.
</Warning>
