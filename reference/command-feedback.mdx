## `feedback log` {#log}

Write a structured feedback entry at the top of `docs/product/feedback-log.md`.

```bash
npx @caesarlo/sdlc-harness feedback log \
  --source <text> --severity <S1|S2|S3|S4> \
  --observation <text> \
  --disposition <Actioned|Deferred|Declined|Monitoring> \
  [--detail <text>] [--date <YYYY-MM-DD>]
```

| Argument | Type | Required | Default | Description |
| --- | --- | --- | --- | --- |
| `--source` | string | Yes | — | Non-empty feedback source, such as a user, ticket, or interview name. |
| `--severity` | enum | Yes | — | Accepts only case-sensitive `S1`, `S2`, `S3`, or `S4`. |
| `--observation` | string | Yes | — | Non-empty observation. Use quotes when it contains spaces. |
| `--disposition` | enum | Yes | — | Accepts only `Actioned`, `Deferred`, `Declined`, or `Monitoring`. |
| `--detail` | string | Conditionally | — | Required to explain the reason when disposition is `Deferred` or `Declined`. |
| `--date` | string | No | Current UTC date | `YYYY-MM-DD` is recommended. The current CLI does not validate the date format. |

The command creates the feedback log when necessary and always inserts the new entry at the top. It exits nonzero for invalid arguments or write failures.
