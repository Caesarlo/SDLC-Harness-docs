功能 verification 证明某个功能的行为；环境命令证明项目能安装、构建、运行或接受端到端检查。两者作用不同。

## 配置项目命令

在 `harness.config.json` 中按需配置：

```json
{
  "commands": {
    "bootstrap": "npm ci",
    "start": "npm run dev",
    "verify": "npm test && npm run build",
    "e2e": "npm run test:e2e",
    "health": "curl --fail http://localhost:3000/health",
    "cleanup": "npm run stop"
  }
}
```

所有键都可选。当前 CLI 的 `env check` 按 `bootstrap`、`verify`、`e2e`、`health` 顺序执行已配置项，并在第一次失败时停止；`start` 和 `cleanup` 用于工作流文档和项目运行约定，不由 `env check` 自动编排后台进程。

## 查看与运行

```bash
npx @caesarlo/sdlc-harness env
npx @caesarlo/sdlc-harness env check
```

参数说明：[列出环境命令](/reference/command-environment#env) · [运行环境检查](/reference/command-environment#env-check)

未配置任何命令时，`env check` 会报告没有内容可检查并成功退出。配置后，每项显示实际命令、PASS/FAIL 和退出码。

## 结束会话

```bash
npx @caesarlo/sdlc-harness session close
```

[查看 `session close` 命令说明 →](/reference/command-environment#session-close)

该命令会：

1. 运行仓库级 `validate`。
2. 运行已配置的环境检查。
3. 汇总当前 commit 和未提交文件数量。
4. 输出功能状态与下一步建议。

审核或环境检查失败会导致非零退出码。未提交变更会明确报告，但它本身不等于失败，因为会话可能有意留下可交接的未提交工作。

<Note>
  `session close` 是只读报告，不会自动提交、更改功能状态、释放 claim 或删除 workspace。请根据报告完成这些动作。
</Note>
