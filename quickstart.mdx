## Prerequisites

- Node.js 22 or later.
- Run commands from the root of the target project repository.
- To run GitHub governance checks or import CI evidence, install the GitHub CLI `gh` and sign in.

This guide uses the full command form, `npx @caesarlo/sdlc-harness`, which requires no prior installation. If you installed the package globally, you can use `sdlc-harness` instead.

## 1. Add SDLC Harness to the repository

<Tabs>
  <Tab title="Existing repository">
    ```bash
    cd your-project
    npx @caesarlo/sdlc-harness adopt
    ```

    [Read the `adopt` command reference →](/reference/command-repository#adopt)

    `adopt` writes only missing files and does not overwrite existing files. If the repository already contains `AGENTS.md`, the tool generates `AGENTS.sdlc-harness.md`. Follow the terminal prompt to reference it from the original `AGENTS.md`; otherwise, new agent sessions cannot discover the harness.
  </Tab>
  <Tab title="Empty or new repository">
    ```bash
    mkdir your-project
    cd your-project
    npx @caesarlo/sdlc-harness init
    ```

    [Read the `init` options →](/reference/command-repository#init)

    `init` stops and lists conflicts when target files already exist. Use `--force` only after confirming that overwriting those files is acceptable.
  </Tab>
</Tabs>

See [Generated files](/getting-started/generated-files) for everything the commands create.

## 2. Enable pre-commit validation

```bash
git config core.hooksPath .githooks
```

Configure this once per clone. The pre-commit hook then runs `validate`.

## 3. Establish a baseline

```bash
npx @caesarlo/sdlc-harness validate
npx @caesarlo/sdlc-harness status
```

Command details: [Audit the repository](/reference/command-repository#validate) · [Read status JSON](/reference/command-repository#status)

A successful audit prints `All checks passed.`. If it fails, fix the errors identified by their category prefixes before starting new work. This separates existing problems from changes you introduce.

## 4. Have the agent read the protocol

You can tell a coding agent:

```text
Read AGENTS.md, feature_list.json, and the current progress.md from the repository root.
Use the SDLC Harness Routing Map to choose the entry point, then work on exactly one ready feature.
```

For repositories that already have `AGENTS.md`, see [Agent onboarding](/getting-started/agent-onboarding).

## 5. Complete your first feature

<Steps>
  <Step title="Select or create a feature">
    Prefer a feature from `readyFeatures` in the `status` output. To create one interactively:

    ```bash
    npx @caesarlo/sdlc-harness new-feature
    ```

    [Read the `new-feature` options →](/reference/command-planning#new-feature)
  </Step>
  <Step title="Start the feature">
    ```bash
    npx @caesarlo/sdlc-harness feature start <feature-id>
    ```

    [Read the `feature start` options →](/reference/command-feature#start)

    The command confirms that dependencies have passed, the feature can receive a `claim`, and the `owner`'s WIP limit will not be exceeded. It then atomically creates the `claim` and changes the feature to `in_progress`.
  </Step>
  <Step title="Implement and run verification">
    ```bash
    npx @caesarlo/sdlc-harness verify <feature-id>
    ```

    [Read the `verify` options →](/reference/command-evidence#verify)

    `verify` executes the automated verification commands declared by the feature and records their exit codes, execution time, and current commit SHA.
  </Step>
  <Step title="Record an independent review">
    ```bash
    npx @caesarlo/sdlc-harness review record <feature-id> \
      --reviewer reviewer-id \
      --summary "Behavior, tests, and boundary checks passed"
    ```

    [Read the `review record` options →](/reference/command-evidence#review-record)

    The reviewer cannot be the `owner` of the feature's `claim`, and a passing review must be newer than the latest passing verification.
  </Step>
  <Step title="Complete the feature and validate the repository">
    ```bash
    npx @caesarlo/sdlc-harness feature complete <feature-id>
    npx @caesarlo/sdlc-harness validate
    npx @caesarlo/sdlc-harness session close
    ```

    Command details: [Complete a feature](/reference/command-feature#complete) · [Audit the repository](/reference/command-repository#validate) · [Close a session](/reference/command-environment#session-close)

    `feature complete` changes the `status` to `passing` only when the `claim`, dependencies, verification for the current commit, and subsequent review are all valid.
  </Step>
</Steps>

<Warning>
  Do not edit the `claim`, evidence, or `passing` status directly to bypass lifecycle commands. The CLI uses atomic writes and records audit events to prevent concurrent overwrites and inconsistent state.
</Warning>
